# Постоянный научный архив Dark-Matter

**Это каталог внутри публичного Git-репозитория, а не хранилище GitHub Actions.** Git-объекты и зафиксированные файлы — основной воспроизводимый источник. Архив работает вместе с [GOAL](../GOAL.md), [PLAN](../PLAN.md), [AGENTS](../AGENTS.md) и отраслевыми журналами.

## Как найти всю хронологию

- [CHRONOLOGY.md](CHRONOLOGY.md) — маршрут по главным событиям, научным выводам и ограничениям.
- [chronology/2026-11-21.md](chronology/2026-11-21.md) и [chronology/2026-11-22.md](chronology/2026-11-22.md) — **историческая реконструкция каждого доступного коммита** с UTC и неизменяемой ссылкой. Рядом JSONL с **полным текстом commit message**. Это учёт *всех 233 коммитов*, достижимых из зафиксированного SHA `2eaf8ce7af7e93106c6afb6fb563ed3cc1ad2235`, а не гарантия, что каждая локальная попытка имела коммит.
- [MILESTONES.md](MILESTONES.md) — карта ключевых научных вопросов, подтверждённых и отрицательных результатов; ссылаться на исходные данные.
- [catalog/RESULTS.md](catalog/RESULTS.md) — прямые неизменяемые ссылки на **83 уже сохранённых** машинных файла JSON/CSV из исходного снимка.
- [catalog/snapshot-2026-11-22.json](catalog/snapshot-2026-11-22.json) — список всех 555 уже хранившихся в Git файлов с Git blob SHA и размерами на момент снимка, **без бессмысленного копирования** каждого файла второй раз.
- [templates/STAGE.md](templates/STAGE.md) — обязательный формат новых существенных исследовательских этапов; создавайте записи в `archive/stages/YYYY/MM/`. Первый этап: [начальная архивация](stages/2026/11/2026-11-22-archive-initialization.md).
- Подробные первичные отчёты и данные уже находятся в `kinetics/`, `cosmology/`, `continuation-*/`, `tests/`, `papers/` и `data/`. Архив ставит на них проверяемые ссылки, но **не перемещает и не удаляет** их.

## Правило обязательной фиксации каждого этапа

**Перед следующим этапом, а при остановке — до завершения сеанса**:

1. Создать/дополнить неизменяемую по смыслу запись `archive/stages/YYYY/MM/YYYY-MM-DD-<slug>.md` по шаблону: постановка, гипотеза, альтернативы, подход и модель, используемые источники и лицензии, исходные данные/версии, параметры и единицы, команды, seed и сетки, наблюдения, численные ошибки, проверки, отрицательные результаты, выводы с границами применимости, последующее действие. Ссылаться на текущие SHA и первичные документы, а не пересказывать всю историю.
2. **В том же коммите сохранить в репозитории** небольшие результаты `*.json`/`*.csv`/`*.txt`/`*.md`, исходный/воспроизводящий код и необходимые фигуры (в существующих каталогах или `archive/stages/.../data/`). Если результат вычислен в Actions, существенные числа, параметры, журнал ошибок и агрегированные данные выгрузить в Git **до истечения срока Actions**. URL Actions — только дополнительное подтверждение, не единственный носитель результата.
3. Дополнить `archive/CHRONOLOGY.md` ссылкой на новый исследовательский этап/решение; пополнить датированный журнал коммитов или использовать их для последующей автоматической индексной реконструкции. Поддерживать [EVIDENCE](../kinetics/research-control/EVIDENCE.md), STATE, NEXT_ACTION и PLAN синхронными. **Не добавлять один файл в несколько копий**: неизменяемый Git SHA + путь к оригиналу достаточны.
4. Не выкидывать неудачные/опровергнутые эксперименты. Исправление связывать с предыдущей записью (`supersedes`/«исправляет») и фиксировать причину. Не заменять наблюдение поздней интерпретацией без следа.
5. Если сохранить исходные гигабайты невозможно — оставить в архиве честное `not_archived`: что отсутствует, почему, публичный источник или контрольная сумма, как воспроизвести. **Нельзя называть это полной архивацией**.

## Порядок восстановления для нового агента

`GOAL.md → PLAN.md → archive/CHRONOLOGY.md → отраслевой GOAL/STATE/NEXT_ACTION → archive/MILESTONES.md → EVIDENCE → нужная запись archive/stages → исходный код и Git SHA`. Не загружать все архивные файлы в контекст сразу; искать по дате, этапу и ссылкам.

## Ограничения и безопасность

- Публичный архив: **никаких API-токенов, паролей, ключей, персональных данных, приватных логов, конфиденциальных файлов или неразрешённых сторонних материалов**. До push проверить содержимое и метаданные. Публикация открыта всему интернету и практически неотзываема из Git-истории.
- Сохранять максимальные **научно значимые** данные, а не мусорные промежуточные сборки, кэши, environment, тысячи одинаковых бинарных дампов. Предпочитать машинно-читаемые компактные форматы и сжатие для уникальных массивов; крупные экспериментальные данные разбивать на разумные наборы. Обычный Git: предупреждение GitHub после 50 MiB на файл, блокировка более 100 MiB; размер репозитория лучше держать ниже 1 ГБ и настоятельно ниже 5 ГБ. Для действительно больших публичных исходных наборов фиксировать DOI/официальный URL, версию, SHA256 и воспроизводящий загрузчик; не дублировать чужую базу без лицензии.
- Не переписывать историю, не использовать force-push и не удалять архивные файлы/ветки без явного решения. Убедиться, что архивные коммиты доступны из долговременных refs; **рабочий draft PR не является автоматическим переносом данных в `main`**.
- Архивные строки — история действий, а **не гарантия физической валидации**. Код, результаты и теоретические утверждения проверять независимо.
