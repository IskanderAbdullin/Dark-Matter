# Независимое сравнение BEST: проверка происхождения и предотвращение ложного результата

**21.11.2026.** Дополнение к [BEST-INDEPENDENT-VALIDATION.md](BEST-INDEPENDENT-VALIDATION.md). Кросс-проверка нашего on-shell источника \(R_{\mathrm{vac}}=0.0164959084596\) должна опираться на **реально исполненный** отдельный код BEST, а не на одинаковые аналитические формулы или единичный неподтверждённый Monte Carlo пробег.

Усилен [best_external_vacuum_reference.py](best_external_vacuum_reference.py): перед импортом внешнего BEST он проверяет Git checkout и выполняет git rev-parse HEAD во внешней директории. Разрешённая версия строго закреплена за SHA **c70875be714e7a6bc6d38578c34bb0dc9f5aefa9** (v1.3.5). Другая ревизия, отсутствие Git или besthep.py приводят к отказу без создания отчёта.

Добавлен [best_source_comparison.py](best_source_comparison.py), читающий **несколько** реально созданных мгновенных rate результатов BEST. Он требует:

1. Отметку реального внешнего запуска плюс SHA, проверенный запускающим скриптом; корректные массу, dof и спин-суммированный матричный элемент.
2. Три независимые интегральные производные числа: материнская меньше нуля, обе дочери больше нуля. Сопоставление бозонного производства с самостоятельным точным 1D on-shell эталоном.
3. Проверку стехиометрии \(\dot n_\phi\approx\dot n_{\chi_2}\approx-\dot n_{\chi_1}\) с отдельной численной относительной невязкой.
4. Как минимум две различные настройки числа q-бинов и две настройки Vegas neval, минимум четыре отчёта. Если меньше — статус остаётся **UNVERIFIED**. Предварительный диагностический порог по скорости и числовым отношениям по умолчанию 10%; настоящий приемлемый порог требуется определять по статистике Monte Carlo и независимому сеточному исследованию.

Файловая проверка не может криптографически доказать, что содержимое JSON не подделано: она лишь проверяет схему и предохраняет от случайного принятия неподтверждённых цифр. Unit-тесты используют **синтетические фикстуры**, чтобы проверить математическую логику порогов, а не выдавать их за настоящее внешнее научное сравнение.

## Режим работы

Без результатов:

    python kinetics/best_source_comparison.py

Ответ: UNVERIFIED: no independently executed BEST results provided. После настоящего выполнения четырех независимых протоколов:

    python kinetics/best_source_comparison.py outputs/best_A.json outputs/best_B.json outputs/best_C.json outputs/best_D.json --output outputs/best_source_comparison.json

Даже при предварительном совпадении мгновенного **вакуумного источника** поле freezeout_or_CLASS_validated всегда false: нелинейное Bose усиление, zero mode, полноценный FRW, SM entropy budget и физический \(f(q)\) не проверены. Для окончательного вывода данные нужно повторять с разными random seeds и оценкой Monte Carlo дисперсии.


## Энергетический контроль добавлен в критерий

После аналитического вывода \(-d\rho_{\chi_1}/dt=M_1\Gamma_{\rm rest}n_{\chi_1}^{\rm FD}\) в [BEST-INDEPENDENT-VALIDATION.md](BEST-INDEPENDENT-VALIDATION.md) модуль сравнения требует от каждого внешнего BEST результата также **три отдельных энергетических производных**. Протокол при M1/T=.1, gχ1=4,T=1,Γ=1 имеет второй независимый benchmark \(R_E=0.03646818570688685\).

Для физически согласованного источника должны выполняться \(\dot\rho_{\chi_1}<0\), \(\dot\rho_{\phi}>0\), \(\dot\rho_{\chi_2}>0\), \(-\dot\rho_{\chi_1}\approx R_E\), \(\dot\rho_{\chi_1}+\dot\rho_\phi+\dot\rho_{\chi_2}\approx0\). Отчёт сохраняет две независимые относительные величины: ошибку величины оттока матери к analytic \(R_E\) и нормированную энергетическую невязку трёх видов. Если эти поля не представлены, preliminary acceptance **отклоняется**, даже если числа частиц идеально согласованы. Это исключает распространённую ошибку: верная скорость распада, но неверное распределение энергии между частицами.

Внешнего **реального** BEST benchmark пока всё ещё нет: обновлённые CI-тесты используют только специально изготовленные положительные/отрицательные фикстуры для проверки самой логики допуска. Реальный stochastic BEST neval и q-grid error необходимо измерить отдельно.
